# 테스트 가이드

> 대상: `features/stop_sign/system/` (정지 표지판 인식 시스템, 2호기 쪽)
> 설계 배경이 궁금하면 [`../../design/README.md`](../../design/README.md) 참고.
> 1호기(GPIO 신호를 받아 실제로 모터를 정지·재개하는 쪽)는 이 리포지토리 범위 밖입니다 —
> 여기서는 **2호기가 표지판을 정상적으로 인식하고, 정해진 규칙대로 GPIO를 켜고 끄는지**까지만 확인합니다.

---

## 0. 시작 전에 알아둘 것

이 테스트는 **라즈베리파이 2호기 하나**에서 진행합니다 (1호기·PC 제어 서버 연동은 별도).

| 확인할 것 | 왜 |
|---|---|
| 2호기에 측면 카메라(USB 웹캠)가 연결돼 있는지 | 카메라가 없으면 `detector.py`가 시작하자마자 에러로 종료됩니다 |
| 2호기가 켜져 있고 같은 Wi-Fi에 연결돼 있는지 | SSH 접속·상태 API 호출에 필요 |
| `config.py`의 `SIDE_CAMERA_INDEX`, `GPIO_OUT_PIN` 값이 실제 환경과 맞는지 | 지금은 플레이스홀더 값입니다 (design/README.md §8 참고) |

> ⚠️ **GPIO 출력을 눈으로 확인하려면**: 아직 1호기 배선이 안 돼 있다면, 2호기의 `GPIO_OUT_PIN`에 LED + 저항을 임시로 연결해두면 HIGH/LOW 전환을 눈으로 볼 수 있습니다. (배선이 없어도 아래 3번처럼 터미널 로그로도 확인 가능합니다.)

## 1. 2호기에서 `detector.py` 실행하기

### 방법 A. 자동 스크립트

```
cd "C:\Users\js033\hee\SW플랫폼_모빌리티_프로젝트\features\stop_sign\system\testguide"
powershell -ExecutionPolicy Bypass -File .\_pi2_run_detector.ps1
```

### 방법 B. 수동 (SSH 직접 접속)

```
ssh mobility_vis@192.168.2.28
cd /home/mobility_vis/stop_sign/pi2_detector
python3 detector.py
```

**정상 시작되면 이런 로그가 뜹니다**:
```
[detector] 시작 — camera=1, gpio_out=17, state_api=http://0.0.0.0:8010/vehicle-state
[detector] driving=False 로 전환
```

`driving=False`가 뜨는 게 정상입니다 — 아직 PC가 "주행 중"이라고 알려준 적이 없어서, `detector.py`는 추론을 생략하고 대기만 합니다 (§3-2).

> IP가 바뀌었으면 `_pi2_run_detector.ps1`, `set_vehicle_state.ps1` 맨 위쪽의 `$PI_IP` 값을 고쳐주세요.

## 2. "주행 중" 상태로 바꿔서 추론 켜기

`detector.py`가 대기 중인 상태에서, **다른** PowerShell 창을 열어서 PC가 하는 일(주행 상태 알림)을 흉내 냅니다.

```
cd "C:\Users\js033\hee\SW플랫폼_모빌리티_프로젝트\features\stop_sign\system\testguide"
powershell -ExecutionPolicy Bypass -File .\set_vehicle_state.ps1 -Driving true
```

`detector.py`가 떠 있는 창에 아래 로그가 뜨면 성공입니다:
```
[detector] driving=True 로 전환
```

이제부터 카메라 프레임을 읽고 실제로 YOLO 추론을 시작합니다.

## 3. 표지판 인식 확인하기

카메라 앞에 정지 표지판(프린트물이든 화면에 띄운 것이든 상관없음)을 가까이 대면, `config.py`의 `DEBOUNCE_N` 프레임만큼 연속으로 잡혔을 때 아래 로그가 뜹니다:

```
[detector] GPIO HIGH — 정지 신호 전송 (쿨다운 5.0s 시작)
```

표지판을 치우고 `DEBOUNCE_M` 프레임만큼 연속으로 안 잡히면:

```
[detector] GPIO LOW — 정지 해제 신호 전송
```

- LED를 달아뒀다면 HIGH일 때 켜지고 LOW일 때 꺼지는지 같이 확인하세요.
- HIGH 로그가 뜬 직후 바로 표지판을 다시 대도, 쿨다운 시간(`COOLDOWN_SECONDS`) 동안은 새 HIGH 로그가 안 뜨는 게 정상입니다 (§3-1 재정지 방지 로직).

---

## 4. "정지" 상태로 되돌려서 추론 끄기 확인

```
powershell -ExecutionPolicy Bypass -File .\set_vehicle_state.ps1 -Driving false
```

`detector.py` 창에 `driving=False 로 전환` 로그가 뜨고, 그 뒤로는 표지판을 갖다 대도 아무 반응이 없어야 정상입니다 (추론 자체를 생략하는 중이므로).

---

## 5. 끝나면 정리하기

`detector.py`가 떠 있는 창(SSH 접속 창)에서 `Ctrl+C`를 눌러 종료합니다.

---

## 테스트 시나리오 예시

1. `detector.py` 실행 → `driving=False`로 대기 상태 확인
2. `set_vehicle_state.ps1 -Driving true` → `driving=True` 전환 확인
3. 표지판을 카메라에 가까이 대기 → `GPIO HIGH` 로그 확인 (LED 있으면 점등도 확인)
4. 표지판을 치움 → `GPIO LOW` 로그 확인 (LED 있으면 소등도 확인)
5. HIGH 직후 바로 다시 표지판을 대봐서, 쿨다운 시간 동안 재신호가 안 뜨는지 확인
6. `set_vehicle_state.ps1 -Driving false` → 표지판을 대도 반응 없는지 확인 (자원 절약 로직 검증)

## 문제가 생겼을 때

| 증상 | 원인 후보 | 확인 방법 |
|---|---|---|
| `detector.py` 실행하자마자 카메라 에러로 종료 | `SIDE_CAMERA_INDEX`가 실제 장치 번호와 다름 | 2호기에서 `v4l2-ctl --list-devices`로 실제 인덱스 확인 후 `config.py` 수정 |
| GPIO 관련 에러 (`GPIO busy` 등) | 다른 프로세스가 같은 핀을 쓰고 있거나, 배선 전이라 핀 번호가 무효 | 다른 GPIO 관련 프로세스 종료 후 재시도, 배선 상태 확인 |
| `set_vehicle_state.ps1` 실행 시 연결 실패 | `detector.py`가 안 켜져 있거나, IP가 바뀌었거나, 방화벽이 8010 포트를 막음 | `detector.py` 창이 살아있는지 확인, `$PI_IP` 값 확인, 2호기 방화벽에서 8010 인바운드 허용 확인 |
| 표지판을 대도 `GPIO HIGH`가 안 뜸 | `driving=False` 상태이거나, confidence가 임계값(`CONFIDENCE_THRESHOLD`)에 못 미침 | 2번 단계로 돌아가 `driving=True` 확인, 표지판을 더 가까이/정면으로 대보기 |
