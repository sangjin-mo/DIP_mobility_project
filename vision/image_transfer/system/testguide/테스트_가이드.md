## 0. 시작 전에 알아둘 것

> ⚠️ **2026-08-23 구조 변경**: 라즈베리파이가 사진을 보내는 대상이 "그때그때 확인한 PC IP"에서 **central 서버 IP `192.168.2.175`로 고정**됐습니다. (출처: `pi_agent/config.py`의 `SERVER_HOST` — `../../design/README.md` §8 참고) **예전에 이 컴퓨터에서 로컬로 테스트할 때 쓰던 주소는 `localhost`/`127.0.0.1`(=이 PC 자신)** 이었는데, 이제는 라즈베리파이가 기본적으로 그 주소로 안 보내므로 아래 A-1/B-4에서 상황별로 나눠 안내합니다.

이 시스템은 **PC 1대 + 라즈베리파이 1대**, 총 두 기기가 서로 통신하면서 동작합니다.

| 기기 | 역할 | 이번 테스트에서 켜야 하는 프로그램 |
|---|---|---|
| **라즈베리파이 2호기** | 웹캠으로 사진 찍기, PC 요청 오면 전송 | `capture.py`(사진 찍기), `upload_server.py`(전송 대기) |
| **PC** | 사진 받아서 보관, 웹 화면 제공 | `main.py`(웹 서버) — **central 서버(`192.168.2.175`)에서 이미 상시 실행 중이면 이 컴퓨터에서 따로 켤 필요 없음** |

프로그램들은 **한 번 켜면 계속 켜져 있어야** 합니다. 그 프로그램이 떠 있는 터미널 창을 닫으면 프로그램도 같이 꺼집니다.

**미리 확인할 것**
- [ ] 라즈베리파이가 켜져 있고, 같은 Wi-Fi에 연결돼 있는지
- [ ] 라즈베리파이의 현재 IP 주소 (모르면 이 대화에서 물어보면 확인해드립니다 — 재부팅할 때마다 바뀔 수 있음)
- [ ] **지금 어떤 방식으로 테스트할지 결정**: ① central 서버(`192.168.2.175`)가 이미 켜져 있어서 그걸 그대로 쓸지, ② 이 컴퓨터에서 옛날처럼 `pc_server`를 단독으로 켜서 로컬 테스트할지 — ②라면 라즈베리파이 쪽 `pi_agent/config.py`의 `SERVER_HOST`를 이 컴퓨터의 현재 IP로 **임시로** 바꿔야 사진이 여기로 옵니다 (테스트 끝나면 `192.168.2.175`로 되돌려주세요)

# 방법 A. 자동 테스트 (스크립트 사용) — 추천

### A-1. 서버 켜기

> 이 스크립트는 **PC 웹 서버(`main.py`)를 이 컴퓨터에서 로컬로** 켭니다 — central 서버(`192.168.2.175`)가 아닙니다. 라즈베리파이의 `pi_agent/config.py`가 지금 `192.168.2.175`로 고정돼 있으므로, 이 컴퓨터에서 로컬 테스트하려면 라즈베리파이 쪽 `SERVER_HOST`를 이 컴퓨터의 현재 IP로 잠깐 바꿔야 "전송 요청" 시 사진이 여기로 도착합니다. (central 서버가 이미 켜져 있다면 이 스크립트를 실행하지 말고 그냥 브라우저로 `http://192.168.2.175:8000/`에 접속하세요.)

Windows 검색에서 **PowerShell**을 열고, 아래를 한 줄씩 입력:

```
cd "C:\Users\js033\hee\SW플랫폼_모빌리티_프로젝트\features\image_transfer\system\testguide"
powershell -ExecutionPolicy Bypass -File .\start_test.ps1
```

몇 초 안에 이런 일이 자동으로 일어납니다:
1. 새 창 A가 뜨고 라즈베리파이에 접속되어 전송 대기 상태가 됨
2. 새 창 B가 뜨고 PC 웹 서버가 켜짐
3. 브라우저가 자동으로 열리며 `http://localhost:8000/` 화면이 뜸

**창 A와 창 B는 닫지 마세요.** (원래 명령을 친 창까지 포함해서 총 3개 창이 열려있는 게 정상입니다.)

> ⚠️ 창 A가 뜨자마자 닫히거나 에러만 뜨면, 라즈베리파이가 꺼져있거나 IP가 바뀐 경우입니다. → [문제가 생겼을 때](#문제가-생겼을-때) 참고.

### A-2. (사진이 필요하면) 촬영하기

브라우저에 사진이 없거나 새 사진이 필요하면, **다른** PowerShell 창을 열어서:

```
cd "C:\Users\js033\hee\SW플랫폼_모빌리티_프로젝트\features\image_transfer\system\testguide"
powershell -ExecutionPolicy Bypass -File .\capture_on_pi.ps1
```

새 창(C)이 뜨고 1초마다 `저장: ...jpg` 로그가 찍힙니다. **5~10장 정도 찍히면 그 창을 클릭하고 `Ctrl+C`**를 눌러 멈추세요. (창을 닫을 필요는 없습니다.)

### A-3. 브라우저에서 테스트하기

→ [브라우저 화면 사용법](#브라우저-화면-사용법-공통) 섹션으로 이동해서 계속하세요.

### A-4. 끝나면 정리하기

원래 명령을 쳤던 첫 번째 창으로 돌아가서:

```
powershell -ExecutionPolicy Bypass -File .\stop_test.ps1
```

PC 서버와 라즈베리파이 쪽 서버가 한 번에 종료됩니다. (스크립트가 띄운 창 A, B, C는 자동으로 안 닫힐 수 있으니 손으로 닫아주세요.)

> IP가 바뀌었으면 `_pi_run_upload_server.ps1`, `_pi_run_capture.ps1`, `stop_test.ps1` 맨 위쪽의 `$PI_IP` 값을 고쳐주세요.

# 방법 B. 수동 테스트 (직접 명령어 입력)

### B-1. 라즈베리파이 접속하기

Windows 검색에서 **PowerShell**을 열고 아래 입력:

```
ssh mobility_vis@192.168.2.28
```

(IP는 예시입니다. 안 되면 알려주세요 — 지금 IP를 다시 찾아드립니다.)

정상 접속되면 프롬프트가 아래처럼 바뀝니다:

```
mobility_vis@VIS:~ $
```

> 이 모양이 안 뜨고 `Permission denied`나 `Connection timed out`이 뜨면 접속 실패입니다. 이 상태로 다음 단계로 넘어가지 마세요.

### B-2. 라즈베리파이에서 사진 찍기

접속된 라즈베리파이 터미널에서:

```
cd /home/mobility_vis/image_transfer/pi_agent
python3 capture.py
```

1초에 한 장씩 아래처럼 로그가 찍히면 정상입니다:

```
저장: /home/mobility_vis/image_transfer/pi_agent/images/2026-08-20/20260820_180001_cam01_001.jpg
저장: /home/mobility_vis/image_transfer/pi_agent/images/2026-08-20/20260820_180002_cam01_001.jpg
```

**사진 5~10장 정도 찍히면 `Ctrl+C`를 눌러서 멈추세요.** (계속 켜둬도 상관은 없지만, 테스트 목적이면 몇 장만 있어도 충분합니다.)

### B-3. 라즈베리파이에서 전송 대기 서버 켜기

같은 터미널에서 (B-2에서 `Ctrl+C`로 멈춘 직후) 이어서:

```
python3 upload_server.py
```

아래처럼 뜨면 성공, **이 창은 그대로 켜둔 채로 최소화만 하세요** (닫지 마세요):

```
INFO:     Uvicorn running on http://0.0.0.0:8001 (Press CTRL+C to quit)
```

### B-4. PC에서 웹 서버 켜기

> central 서버(`192.168.2.175`)가 이미 켜져 있다면 이 단계는 건너뛰고 브라우저로 `http://192.168.2.175:8000/`에 바로 접속하면 됩니다. 이 컴퓨터에서 직접 로컬로 띄우려면(예전 방식, `localhost`/`127.0.0.1`), B-2에서 접속한 라즈베리파이 쪽 `pi_agent/config.py`의 `SERVER_HOST`(현재 `192.168.2.175`로 고정)를 이 컴퓨터의 현재 IP로 임시로 바꿔야 사진이 여기로 옵니다.

**새로운** PowerShell 창을 하나 더 엽니다 (B-3 창은 그대로 두고). 새 창에서:

```
cd "C:\Users\js033\hee\SW플랫폼_모빌리티_프로젝트\features\image_transfer\system\pc_server"
py -m uvicorn main:app --host 0.0.0.0 --port 8000
```

아래처럼 뜨면 성공, **이 창도 닫지 말고 그대로 두세요**:

```
INFO:     Uvicorn running on http://0.0.0.0:8000 (Press CTRL+C to quit)
```

> 지금까지 총 3개의 터미널 창이 열려 있어야 정상입니다.
> ① 라즈베리파이 SSH 접속 창(B-3에서 `upload_server.py` 실행 중)
> ② PC 웹 서버 창(방금 B-4에서 실행)
> ③ (선택) 사진을 더 찍고 싶을 때 쓸 여분의 SSH 창

### B-5. 브라우저에서 테스트하기

브라우저에서 `http://localhost:8000/` 접속 → [브라우저 화면 사용법](#브라우저-화면-사용법-공통) 섹션으로 이동해서 계속하세요.

### B-6. 끝나면 정리하기

각 터미널 창에서 `Ctrl+C`를 누르면 해당 프로그램이 꺼집니다. 순서는 상관없습니다.

- PC 웹 서버 창 → `Ctrl+C`
- 라즈베리파이 SSH 창(`upload_server.py` 실행 중) → `Ctrl+C`, 그 다음 `exit`으로 SSH 접속도 종료

## 브라우저 화면 사용법 (공통)

방법 A, B 어느 쪽으로 시작했든 브라우저에서 보이는 화면과 사용법은 동일합니다.

크롬이나 엣지에서 주소창에 입력 (방법 A는 자동으로 이미 열려있음):

```
http://localhost:8000/
```

**VIS 통합 서버** 화면이 뜨면 성공입니다. 이 화면에서 할 수 있는 것들:

### ① 전송 요청
파란색 **"전송 요청"** 버튼 클릭 → 라즈베리파이에 찍혀있던 사진들이 PC로 넘어옵니다. 잠시 후 화면 오른쪽에 "전송 완료 — 요청 N장 / 성공 N장 / 실패 0장" 메시지가 뜨고, 화면이 자동 새로고침되며 사진 썸네일이 나타납니다.

### ② 전체 선택
그리드 위쪽의 **"전체 선택"** 체크박스를 누르면 아래 모든 사진에 체크가 됩니다. (하나씩 클릭해도 됩니다.)

### ③ 선택 항목 삭제 (PC)
체크한 사진들을 **PC 화면·저장소에서만** 지웁니다. 확인 창이 뜨는데 "확인"을 누르면 새로고침 없이 바로 그 사진들이 화면에서 사라집니다. (라즈베리파이 쪽 원본에는 영향 없습니다.)

### ④ 라즈베리파이 로컬 저장소 전체 삭제
**라즈베리파이 안**에 남아있는, 이미 PC로 전송이 끝난 사진들을 전부 지웁니다. 확인 창에서 "확인"을 누르면 실행됩니다. (PC 화면의 사진들은 그대로 남아있습니다 — PC가 "정식 보관소" 역할이라 일부러 안 지워집니다.)

> ⚠️ 아직 PC로 전송 안 된 사진은 이 버튼을 눌러도 안 지워집니다 (안전장치). "삭제 완료 N장 (미전송이라 보존됨: M장)" 메시지로 확인 가능합니다.

### ⑤ 분석 시작 (준비중)
회색 비활성 버튼입니다. 아직 구현 전이라 눌러도 반응 없는 게 정상입니다 (향후 AI 분석 기능이 여기에 연결될 자리입니다).

## 테스트 시나리오 예시

처음이라면 이 순서대로 한 번 쭉 해보는 걸 추천합니다. (방법 A, B 둘 다 적용됩니다.)

5. (선택) 라즈베리파이 터미널에서 `ls images/2026-08-20/` 쳐서 실제로 비어있는지 확인

## 문제가 생겼을 때

| 증상 | 원인 후보 | 확인 방법 |
|---|---|---|
| 브라우저에서 `localhost:8000` 접속 안 됨 | PC 웹 서버 창이 꺼져있음 | 그 터미널 창이 살아있는지, `Uvicorn running` 문구가 있는지 확인 |
| "전송 요청" 눌렀는데 에러(`pi_unreachable`) | 라즈베리파이 `upload_server.py`가 꺼져있거나, IP가 바뀜 | 해당 창이 살아있는지 확인. IP가 바뀌었으면 `pc_server/config.py`의 `PI_HOST` 값(방법 B) 또는 스크립트 상단 `$PI_IP` 값(방법 A)도 같이 바꿔야 함 |
| "전송 요청"은 성공했다는데(에러 없음) 이 컴퓨터 화면엔 사진이 안 뜸 | 라즈베리파이가 사진을 이 컴퓨터가 아니라 **central 서버(`192.168.2.175`)로 보냈음** | 라즈베리파이 `pi_agent/config.py`의 `SERVER_HOST`가 지금 뭘로 돼 있는지 확인. 이 컴퓨터에서 로컬 테스트하려면 이 컴퓨터의 현재 IP로 임시로 바꿔야 함(§0 참고), 아니면 그냥 `http://192.168.2.175:8000/`에서 확인 |
| 사진이 하나도 안 보임 | 아직 "전송 요청"을 안 눌렀거나, 라즈베리파이에 사진이 없음 | 사진 찍는 단계로 돌아가서 사진부터 찍기 |
| "라즈베리파이 로컬 저장소 전체 삭제" 눌렀는데 0장만 지워짐 | 애초에 전송 완료된 사진이 없었음 (정상 동작) | "전송 요청"을 먼저 눌러서 성공 처리된 사진을 만든 뒤 재시도 |
| (방법 A) `.ps1 파일을 실행할 수 없습니다` 에러 | `-ExecutionPolicy Bypass`를 빼먹음 | 반드시 `powershell -ExecutionPolicy Bypass -File .\파일명.ps1` 형태로 실행 |
