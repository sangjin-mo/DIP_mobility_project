## 2026-08-22

- **표지판 인식(stop_sign) 설계 착수** — YOLOv8n(COCO `stop sign`) 사전학습 모델을 파인튜닝 없이 채택, 0단계 검증에서 근접 촬영 시 confidence 0.86~0.96 확인
- 2호기 실기(작물 카메라 임시 대여)로 표지판 인식 → GPIO 출력 → 재출발까지 end-to-end 하드웨어 검증 성공
- 1호기 실제 코드(`drive_ver3`) 대조 후 **GPIO 해석 정정**: 상승엣지 1회 트리거만 동작, 자동 재출발 없음(재출발은 사람이 대시보드 START를 눌러야 함)
- **GPIO 핀 직결 방식 폐기** — 점퍼케이블 연결이 물리적으로 불가능해짐 → 정지 신호를 PC `web_dashboard` 경유 HTTP(`POST /api/control/stop`)로 전환
- 정차 중 자원 절약 방식 변경: PC가 `POST /vehicle-state`로 푸시하는 방식(호출해줄 주체가 없어 무효) → 2호기가 `GET /api/control/status`를 1초 주기로 직접 폴링하는 방식으로 전환
- **mediapipe(제스처 인식) 도입 검토 시작** — 정지(주먹)/가속(따봉)/감속(역따봉) 3종 제스처를 표지판 인식과 같은 카메라로 처리하는 방향으로 설계
- 2호기 실기에서 mediapipe 공식 패키지 실행 시 **SIGILL 크래시 블로커 발견**(Cortex-A72 AES 명령어 미지원) → 원인 분석 후 TFLite 서브모델을 직접 호출하는 자체 파이프라인 개발 착수, 크롭/회전 버그 수정을 거쳐 **주먹→STOP, 따봉→속도변경 end-to-end 성공**(단, 프로덕션 코드에는 아직 미통합 — §2026-08-23 참고)

## 2026-08-20
